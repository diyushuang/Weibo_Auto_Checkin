Cookie 保活

定期用 Cookie 请求微博接口，把轮换的新凭证续下来
小时；按实测寿命会自动加密，签到时段的保活会自动让路
小时；Cookie 临近预计失效时改用更短间隔抢救，业务流量掺入更频繁
天；服务端 session 实际能活多久（微博通常约 7 天）
距预计失效不足几天时推送 TG
同一账号两次提醒的最小间隔，避免刷屏
如 0-6 表示 0 点至 6 点不保活（off 关闭）；真人不会 24 小时在线
保活轮内两个账号之间的等待秒数
一轮最多处理多少个账号，其余下轮继续
小时；临期且超过该时长仍无成功换发时，面板横幅与 TG 预警会建议扫码续期
如 https://panel.example.com；填了之后 TG 的 Cookie 预警会附带面板链接，方便手机上直接打开扫码
临期时额外请求 PC 端候选端点尝试换发新凭据；微博未承诺有效性，建议先用 CLI rotate-probe 实测
逗号分隔，仅允许微博域名；rotate-probe 实测有效后回填这里

📥 批量导入账号

每行一个账号，支持以下格式：

  • 纯 Cookie（自动命名为「微博账号1」「微博账号2」…）
  • 名称|Cookie（名称与 Cookie 用 | 分隔）
  • 以 # 开头的行视为注释，自动跳过

📂 从文件导入账号

选择之前导出的 JSON 文件，会自动跳过已存在的账号（按名称判断）。

📱 微博扫码添加账号

使用 微博 App 扫描二维码并在手机上确认。确认后系统会自动获取微博昵称并导入账号。

扫码成功后新 Cookie 会自动覆盖同微博号的原账号（代理、备注、启用状态保留），无需删除重建。
